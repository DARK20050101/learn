# Phase 10.2 题目生产规范

适用范围：数学、物理、英语第一批题库扩充  
目标用户：青海西宁准高三学生  
知识点版本：`kp-mapping-v1.1`  
导入方式：现有 JSON 导入器  
质量检查：Phase 10.1 `question_bank` CLI

## 1. 基本原则

每道题必须做到：

- 题干完整、无歧义。
- 正确答案唯一或评分标准明确。
- 解析能够说明“为什么”，不能只重复答案。
- 有且仅有一个标准 primary 知识点。
- 难度符合暑假训练场景。
- 来源可追溯。
- 通过 CLI 检查和人工审核后才能导入。

AI 可以协助生成草稿，但不能直接批准、导入或发布题目。

## 2. 标准题目 JSON 格式

一个文件可以是：

- 单个题目对象；
- 题目对象数组；
- 包含 `questions` 数组的对象。

推荐批量文件格式：

```json
{
  "questions": [
    {
      "subject": "数学",
      "chapter": "函数",
      "knowledge_points": [
        "函数的单调性"
      ],
      "difficulty": 2,
      "type": "single_choice",
      "question": "已知函数 f(x)=2x+1，则该函数在 R 上（ ）。",
      "options": [
        "单调递增",
        "单调递减",
        "先增后减",
        "不具有单调性"
      ],
      "answer": "A",
      "solution": "一次函数 f(x)=kx+b 中，k=2>0，因此函数在 R 上单调递增，选择 A。",
      "source": "原创·Phase10.2·数学函数·批次01",
      "title": "一次函数单调性判断",
      "tags": [
        "kp:MATH-FUNCTION-MONOTONICITY",
        "grade:high-school",
        "origin:original"
      ]
    }
  ]
}
```

文件必须使用 UTF-8 编码。建议每个批次包含 20—50 道题，避免一次导入过多、难以审核。

## 3. 字段填写规则

### 3.1 `subject`

必填字符串，只允许当前题库支持的标准学科名称：

```text
数学
物理
英语
```

不能使用“高数”“高中物理”“English”等变体。

### 3.2 `chapter`

必填字符串，填写学生和教师能够理解的教材章节名称。

要求：

- 与题目 primary 知识点所属模块一致。
- 同一章节使用统一名称。
- 不写教材页码、试卷名称或题型。
- 不使用“综合”“其他”“练习一”等无法定位内容的名称。

示例：

```text
函数
匀变速直线运动
非谓语动词
定语从句
阅读理解
```

### 3.3 `knowledge_points`

必填字符串数组，至少包含一个非空名称。

第一批扩充规则：

- 填写标准三级知识点中文名称。
- 第一项必须对应 primary code。
- 不填写学科名、章节名、题型或能力标签。
- 不使用 deprecated、redirected 或 ability-only 节点名称。
- 同一道题不重复填写近义名称。

示例：

```json
"knowledge_points": ["函数的定义域"]
```

虽然字段支持多个名称，第一批扩充默认只填写一个 primary 知识点。只有人工审核明确认定
存在必要 secondary 时，才允许添加其他名称，并在批次审核记录中说明。

### 3.4 `difficulty`

必填整数，只允许 `1—5`。具体定义见第 5 节。

### 3.5 `type`

必填，只允许：

| 值 | 含义 |
|---|---|
| `single_choice` | 单项选择题 |
| `multiple_choice` | 多项选择题 |
| `true_false` | 判断题 |
| `short_answer` | 简答、计算或翻译题 |
| `fill_blank` | 知识点记忆填空（概念、定义、公式） |

题型必须与 `options` 和 `answer` 的数据形态一致。

### 3.6 `question`

必填题干。

要求：

- 学生仅阅读题干和选项即可理解任务。
- 数学符号、物理单位、英文标点书写一致。
- 已知条件完整。
- 不依赖缺失的图片、表格或上文。
- 不出现“如下图”“根据材料”等无对应内容的表述。
- 不泄露答案。
- 不包含命题人备注、审核意见或提示词。

如果题目确实依赖图片，第一批扩充暂不收录，等待系统具备稳定的图片题能力。

### 3.7 `options`

选择题必填，判断题、简答题和填空题必须为空数组或省略。
选择题规则：

- 至少两个选项；通常使用四个。
- 每个选项非空。
- 选项内容不能完全重复。
- 选项结构、单位和语法形式尽量一致。
- 干扰项必须有合理错误来源。
- 不使用“以上都正确”“以上都不正确”，除非确有教学价值。
- 避免通过选项长度、语气或格式暗示答案。

### 3.8 `answer`

必填，数据形态由题型决定。

单选题：

```json
"answer": "A"
```

也可以填写完整选项文本，但推荐使用字母，便于人工校对。

多选题：

```json
"answer": ["A", "C"]
```

判断题：

```json
"answer": true
```

简答题：

```json
"answer": "2"
```

简答题当前采用规则判题，答案必须尽量标准化。存在多个等价表达、复杂推导或开放答案时，
必须先确认当前判题能力是否适用，否则暂不导入。

填空题（`fill_blank`）：

```json
"answer": "叶绿体"
```

```json
"answer": ["叶绿体", "叶绿体细胞"]
```

填空用于概念、定义和公式的记忆类题目，题干用下划线表示空位。`answer` 可以是一个字符串，
也可以是多个可接受答案组成的数组（同义词/别名），任意一个匹配即判为正确。判题忽略空格、
全半角、大小写和常见标点差异；存在无法用字符串表达或需要区分中间过程的答案时，暂不导入。

### 3.9 `solution`

必填标准解析，质量要求见第 7 节。

### 3.10 `source`

必填来源说明，规范见第 6 节。

### 3.11 `title`

可选，最长 200 字符。

建议填写简短、可检索的题目名称，例如：

```text
一次函数单调性判断
匀变速运动速度计算
定语从句关系词选择
```

不填写时，导入器会使用“章节 · 第一个知识点”自动生成。

### 3.12 `tags`

可选字符串数组。第一批扩充强烈要求包含 primary code：

```json
"tags": ["kp:MATH-FUNCTION-MONOTONICITY"]
```

建议标签：

| 格式 | 用途 |
|---|---|
| `kp:<code>` | 标准 primary 知识点 |
| `origin:original` | 人工原创 |
| `origin:ai-draft` | AI 生成后人工审核 |
| `origin:adapted` | 根据合法来源改编 |
| `grade:high-school` | 高中范围 |
| `reviewed:teacher` | 已完成教师审核 |

同一题只能有一个 primary `kp:<code>`。标签不能保存答案、提示词、学生隐私或密钥。

## 4. knowledge_point_code 选择规则

### 4.1 只选择标准三级节点

primary code 必须满足：

- 存在于当前 `knowledge_points`。
- `level=3`。
- `is_active=true`。
- 学科与题目 `subject` 一致。
- 属于 `kp-mapping-v1.1` 正式节点。

不能选择：

- 一级学科节点，如 `MATH`。
- 二级模块节点，如 `MATH-FUNCTION`。
- redirected 历史节点。
- deprecated 节点。
- ability-only 节点。
- 为单道题临时编造的新 code。

### 4.2 选择方法

按以下顺序判断：

1. 题目最终要求学生完成什么。
2. 决定正确答案所需的核心知识是什么。
3. 如果去掉某个知识点，学生是否仍能稳定作答。
4. 在现有目录中选择粒度最合适的三级节点。
5. 在 `tags` 写入对应 `kp:<code>`。
6. 确认 `knowledge_points` 中文名称与 code 一致。

不要仅根据题目中出现的名词选知识点。例如题干出现“函数”，但实际考查的是集合运算，
primary 应选择集合，而不是函数。

### 4.3 一题多个知识点

第一批题库采用保守原则：

- 每题恰好一个 primary。
- primary 是决定推荐、覆盖统计和学习画像的核心节点。
- 不因题目包含多个步骤就自动添加多个知识点。
- secondary 必须由学科审核人明确确认。

如果无法判断唯一 primary，题目应退回修改，不得以宽泛章节节点代替。

### 4.4 历史 code 兼容

以下旧 code 不能用于新题：

| 禁止使用的旧 code | 新题应使用 |
|---|---|
| `MATH-SET-INTERSECTION` | `MATH-SET-OPERATIONS` |
| `PHY-KINEMATICS-VELOCITY-EQUATION` | `PHY-KINEMATICS-UNIFORM-ACCELERATION` |
| `PHY-OPTICS-REFRACTION-PHENOMENON` | `PHY-OPTICS-REFRACTION` |
| `ENG-CLAUSE-RELATIVE-THAT` | `ENG-CLAUSE-RELATIVE-WORD-SELECTION` |
| `ENG-CLAUSE-RELATIVE-WHERE` | `ENG-CLAUSE-RELATIVE-WORD-SELECTION` |
| `ENG-GRAMMAR-MODAL-MUST` | `ENG-GRAMMAR-MODAL-BASIC` |

`ENG-WRITING-SENTENCE-EXPRESSION` 已降级为能力标签，不能作为 primary。

### 4.5 目录中没有合适 code

禁止在 JSON 中自行发明 code。

处理流程：

1. 暂停该题生产。
2. 记录候选知识点名称、学科、父模块和至少 5 道未来题目样例。
3. 发起独立知识目录评审。
4. 目录变更完成后重新执行 CLI 检查。

题目生产不能绕过知识目录治理。

## 5. difficulty 1—5 定义

难度表示目标学生在掌握对应基础知识后的作答负担，不等同于题目文字长度。

| 难度 | 定义 | 典型特征 | 暑假用途 |
|---:|---|---|---|
| 1 | 基础识记 | 直接辨认定义、公式、词义或单一步骤 | 建立信心、错误后降阶 |
| 2 | 基础应用 | 一个核心知识点，少量计算或语境判断 | 每日训练主体 |
| 3 | 常规综合 | 两到三个步骤，需要选择常规方法 | 每日训练主体 |
| 4 | 较强综合 | 条件转换、易错变式或较复杂推理 | 掌握稳定后的提升 |
| 5 | 高难综合 | 多模块综合、压轴思路或高认知负荷 | 少量挑战，不作为主体 |

### 5.1 难度判断参考

命题人与审核人共同考虑：

- 所需知识点数量。
- 推理或计算步骤。
- 是否需要隐含条件转换。
- 干扰项迷惑程度。
- 阅读量和信息提取负担。
- 对常见方法熟练度的要求。

不能因为数字大、文字长或英文单词生僻就简单标为高难度。

### 5.2 第一批建议分布

单个批次建议：

- 难度 1：10%—20%
- 难度 2：30%—40%
- 难度 3：30%—40%
- 难度 4：10%—20%
- 难度 5：不超过 10%

题量较小时不强求精确比例，但必须避免全部集中在同一难度。

## 6. source 字段规范

`source` 必须让审核人员能够判断题目来源和版权风险。

### 6.1 人工原创

```text
原创·Phase10.2·数学函数·批次01
```

### 6.2 AI 草稿后人工改写

```text
AI草稿·人工复核·Phase10.2·物理直线运动·批次01
```

同时添加：

```json
"tags": ["origin:ai-draft", "reviewed:teacher"]
```

### 6.3 合法公开材料改编

```text
改编·材料名称·发布机构·年份·原题编号
```

必须保留来源链接或内部审核记录。不得仅填写“网络”“百度”“GitHub”等模糊描述。

### 6.4 校内或教师提供

```text
教师提供·学科·提供人编号·日期·批次
```

不在公开题目字段中保存教师手机号、身份证号等个人信息。

### 6.5 禁止情况

- 来源不明的付费题库复制。
- 无授权整套搬运试卷。
- 删除原来源后冒充原创。
- 把 AI 模型名称当作唯一质量证明。

## 7. 解析质量标准

合格解析必须包含：

1. 本题考查的关键知识或规则。
2. 从条件到答案的关键步骤。
3. 正确答案及其成立原因。
4. 必要时说明常见错误或干扰项为什么不成立。

### 7.1 数学

- 写出关键公式、变形或推理依据。
- 不能只给最终数值。
- 注意定义域、取值范围、正负号和分类讨论。
- 多种解法并非必需，但标准解法必须完整可靠。

### 7.2 物理

- 明确研究对象、物理过程和适用规律。
- 公式中的物理量含义清楚。
- 单位和方向不能省略到产生歧义。
- 区分矢量与标量，避免只代公式不解释条件。

### 7.3 英语

- 说明语法规则、语境或定位依据。
- 词汇题说明搭配或上下文逻辑。
- 阅读题指出答案对应的原文信息或推断链。
- 不能只写“根据句意可知选 A”。

### 7.4 不合格解析示例

```text
答案是A。
显然选B。
代入公式即可。
根据句意可知。
```

解析建议不少于一个完整解释句。CLI 的“解析过短”只作为初筛，最终由人工判断。

## 8. 人工审核 Checklist

每道题必须由审核人逐项确认。

### 8.1 内容正确性

- [ ] 题干条件完整，无缺失图片或材料。
- [ ] 题目在高中范围内。
- [ ] 正确答案经过独立作答确认。
- [ ] 单选题只有一个正确答案。
- [ ] 多选题所有正确选项均已列出。
- [ ] 简答题适合当前规则判题。
- [ ] 填空题至少一个可接受答案，同义词/别名完整。
- [ ] 数学符号、物理单位和英文拼写正确。

### 8.2 知识点与难度

- [ ] 有且仅有一个 primary `kp:<code>`。
- [ ] code 是启用的标准三级节点。
- [ ] code 学科与 `subject` 一致。
- [ ] 中文知识点名称与 code 一致。
- [ ] 未使用 redirected、deprecated 或 ability-only 节点。
- [ ] `chapter` 与知识点模块一致。
- [ ] 难度经过独立复核。

### 8.3 选项与解析

- [ ] 选项无重复、无明显格式暗示。
- [ ] 干扰项来源合理。
- [ ] 解析包含关键规则和步骤。
- [ ] 解析没有与答案冲突。
- [ ] 解析适合准高三学生阅读。
- [ ] 没有仅重复答案。

### 8.4 来源与合规

- [ ] `source` 可追溯。
- [ ] 原创、改编或 AI 草稿标识正确。
- [ ] 不存在明显版权搬运风险。
- [ ] 不包含学生、教师或第三方隐私。

### 8.5 工具检查

- [ ] `lint` 无 Error。
- [ ] `verify <file>` 无 Error。
- [ ] 数据库重复数为 0。
- [ ] 难度分布已检查。
- [ ] 本批次确实改善目标知识点覆盖。

任何一项未确认，题目必须退回草稿区。

## 9. AI 生成题审核流程

AI 只负责产生候选草稿，人工对最终题目承担责任。

```text
人工确定学科、知识点code、题型和难度
  ↓
AI生成候选题干、选项、答案、解析
  ↓
保存为draft，并标记origin:ai-draft
  ↓
命题人逐题独立作答
  ↓
检查答案唯一性、事实和计算
  ↓
人工重写歧义题干、弱干扰项和空泛解析
  ↓
运行lint
  ↓
学科审核人二次审核
  ↓
运行verify及统计命令
  ↓
批准后进入approved目录
```

### 9.1 AI 生成前的输入约束

人工必须先确定：

- 标准知识点 code。
- 学科和章节。
- 题型。
- 目标难度。
- 是否允许使用情境材料。
- 解析必须包含的关键步骤。

不能让 AI 自行扩展知识目录或自行决定正式 code。

### 9.2 AI 生成后的强制检查

- 重新计算所有数学和物理答案。
- 核对英文语法、搭配和语境自然度。
- 检查是否存在多个合理答案。
- 检查选项是否泄露答案。
- 检查题干与解析是否自相矛盾。
- 检查是否虚构教材、政策、人物或来源。
- 检查是否与现有题高度重复。
- 检查难度是否与指定等级一致。

### 9.3 AI 题的禁止行为

- 未经人工阅读直接批量导入。
- 用 AI 自评代替教师审核。
- 让 AI 自动把 warning 标记为已接受。
- 自动生成不存在的知识点 code。
- 把模型输出中的引用当作真实来源。
- 仅替换数字或人名制造大量低价值变体。

第一批 AI 生成题建议 100% 人工审核。

## 10. 导入前必须通过的 CLI 检查

以下命令均为只读分析，不会自动导入或修改题库。

### 10.1 JSON 格式与基础质量

```powershell
python -m app.cli.question_bank lint `
  data/question_bank/drafts/math_function_batch01_v1.json `
  --report data/question_bank/reports/math_function_batch01_lint.md
```

通过标准：

- `errors=0`
- 文件内重复为 0
- warning 已逐条人工处理

### 10.2 数据库感知的导入前预检查

```powershell
python -m app.cli.question_bank verify `
  data/question_bank/drafts/math_function_batch01_v1.json `
  --report data/question_bank/reports/math_function_batch01_verify.md
```

通过标准：

- 所有知识点 code 存在。
- 所有 code 为启用的三级节点。
- 学科一致。
- 每题能够解析到唯一 primary。
- 数据库重复为 0。
- `errors=0`，命令退出码为 0。

### 10.3 知识点覆盖基线

```powershell
python -m app.cli.question_bank coverage `
  --subject 数学 `
  --report data/question_bank/reports/math_coverage_before.md
```

审核人需要确认本批次主要补充题量不足的知识点。

### 10.4 难度分布

```powershell
python -m app.cli.question_bank difficulty `
```

## 11. 第一批题库建议

第一批不追求一次达到 500 道，建议：

- 每个学科先选择 3—5 个最缺题的知识点。
- 每个知识点新增 5—10 道。
- 以难度 2—3 为主。
- 每批 20—50 道。
- 一个文件尽量只包含一个学科。
- 每完成一批，重新运行 coverage、difficulty 和 missing。

先验证生产质量和学生使用效果，再逐步扩大题量。
